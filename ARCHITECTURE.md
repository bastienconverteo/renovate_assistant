# Architecture (v0.2, 2026-10-08)

Plain files in git on Bastien's Mac. Any AI tool can use them; Claude is only the first interface.

## Layers (read top down, stop when answered)
| Layer | Files | Size rule | Written by |
| --- | --- | --- | --- |
| Rules | `AGENTS.md` | under 70 lines | Bastien + assistant |
| Stable facts | `CONTEXT.md`, `GLOSSARY.md` | under 60 lines; no dated logs | assistant |
| Generated index | `index/digest.md` (open items), `index/catalog.csv` (one line per item), `index/links.csv` (every link) | regenerated by `pm.py build` | tool only |
| Narrative | `STATUS.md`, `summaries/` | under 30 lines each | assistant |
| Registers (truth) | `registers/*.csv` + `schema.json` | one fact, one row | `pm.py add/set` |
| Extracts | `extracts/` | one per source | assistant |
| Raw | `raw/` (unchanged originals), `inbox/` (incoming, git-ignored) | never edited | Bastien |

## Entity model
Every item has an ID, a `topic` (fixed list in `schema.json`), `evidence` (documented, verbal, analysis, inferred), `src` (SRC IDs) and `updated`.
- Sources (SRC): every input, with paths to raw and extract.
- Meetings (MTG): attendees, decisions and actions they produced.
- Requirements (REQ), datapoints (DP, with definitions in `datapoint_defs.csv`), KPIs (CAKPI), decisions (DEC), actions (ACT), commitments (COM), blockers (BLK), assumptions (ASM), stories (STO), stakeholders (STK).
- Questions (QST): every open question and every conflict between sources.

## Linking
Any ID written in any cell is a link (for example `links`, `requirement_ids`, `about`, or free text). KPI `supergold_fields` are resolved to DP IDs by name. `pm.py build` writes all links to `index/links.csv`; `pm.py impact ID` walks them in both directions. Sources and items with more than 25 links are hubs: listed, not expanded.

## Flows
- Ingest: inbox or paste → raw + extract + SRC row → register rows via `pm.py` → build → ingest-log line → commit.
- Ask: digest → `pm.py show / impact / find` → extract only if needed.
- Weekly: Monday prep-meeting, Tuesday workbook ingest, Thursday reconcile transcript, Friday exec-update.

## Integrity
`pm.py check` validates headers, enum values, topics, SRC references, duplicate IDs and dangling links. A commit should only happen with check ok.

## How to ask (day to day)
- Ask in the project chat, one message per question. Each question gets its own thread. The thread starts with no chat history and reads the repo (AGENTS → CONTEXT → digest → `pm.py`). Answers stay consistent because the repo is the only memory.
- Keep follow-ups on the same subject in that subject's thread. Start a new message for an unrelated subject: a fresh thread costs about 11 KB of startup reading, while a long thread gets more expensive with every turn.
- Inputs: drop files in `inbox/` and say "ingest". Paste emails and ServiceNow threads into the message. Personal data stays in `inbox/` only.
- Anything decided or learned in a thread must be written to the repo (`pm.py add/set`, commit). Otherwise it is lost when the thread ends.
- The same rules work outside Claude Projects: Claude desktop or Claude Code opened on this folder reads `AGENTS.md` first.
